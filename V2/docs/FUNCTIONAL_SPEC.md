# SmartCook V2 功能說明：煎台漢堡

> 狀態：草稿 v2（2026-11-24）。標 **【待確認】** 的地方要現場試過或決定後再補。

## 1. 目標

用 Kawasaki F60 雙臂在**真的加熱的煎台**上煎漢堡排，再組成一個完整的漢堡：
從取料區夾肉排 → 放上煎台 → 煎 → 翻面 → 鏟起 → 組裝（麵包、肉排、配料）→ 出餐。

V2 沿用 V1 的整體架構（觸控介面 → 流程狀態機 → TCP 指令 → 雙臂 AS 程式，加上 YOLO 視覺），
但**只做漢堡**，V1 的生菜沙拉菜色不保留（需要時從 `V1/` 取回）。

已決定的事項：

| 項目 | 決定 |
|---|---|
| 煎台 | 真的加熱 |
| 每面煎幾秒、翻幾次 | 做成參數，現場實際試出來 |
| 肉排來源 | 最終從取料區夾；開發初期可以直接從煎台開始 |
| 成品 | 組成完整的漢堡 |
| 翻面工具 | 換成平鏟，機構重新設計 |
| 視覺 | 重新訓練 YOLO 模型辨識肉排與漢堡食材 |
| V1 沙拉菜色 | 不保留 |

## 2. 展示流程（完整版）

| # | 階段 | 動作 | 負責手臂 |
|---|---|---|---|
| 1 | `INIT` | 連線、握手、兩臂回原點、確認煎台溫度 | 雙臂 |
| 2 | `PICKUP` | 視覺定位取料區的生肉排；右鏟把肉排刮上左鏟 | 雙臂（左鏟接、右鏟刮） |
| 3 | `PLACE` | 左鏟端到煎台；右鏟擋在肉排後面、左鏟抽出，肉排落到煎台 | 雙臂 |
| 4 | `FRY` | 煎第一面，計時；兩臂退到安全位置 | — |
| 5 | `FLIP` | 平鏟鏟入肉排底下 → 翻面 → 退開 | 左臂翻、右臂輔助 |
| 6 | `FRY` | 煎另一面（4–6 依參數重複） | — |
| 7 | `SCOOP` | 左鏟鏟起熟肉排 → 保持水平端到出餐盤 → 右鏟擋住、左鏟抽出，肉排落在盤子上（之後改成組裝區、下層麵包上） | 雙臂（左鏟端、右鏟擋） |
| 8 | `ASSEMBLE` | 依組裝順序疊上麵包、肉排、配料（見第 4 節） | 雙臂 |
| 9 | `HOME` | 兩臂回原點 | 雙臂 |

流程階段：`INIT → PICKUP → PLACE → FRY → (FLIP → FRY) × N → SCOOP → ASSEMBLE → HOME`

## 3. 分階段開發

先從簡單的版本跑通，每一階段在實機上驗證後再往下：

| 階段 | 內容 | 起點 | 完成條件 |
|---|---|---|---|
| **A. 煎台翻面** | 人工把肉排放上煎台，手臂只做 `FRY → FLIP → FRY` | 肉排已在煎台 | 平鏟能穩定翻面，不掉出煎台 |
| **B. 鏟起出餐** | 加上 `SCOOP`，把熟肉排放到盤子 | 肉排已在煎台 | 鏟起不破、不掉 |
| **C. 取料上煎台** | 加上 `PICKUP → PLACE`，從取料區夾生肉排 | 取料區 | 視覺定位 + 夾取穩定 |
| **D. 組裝漢堡** | 加上 `ASSEMBLE` | 取料區 | 完整漢堡出餐 |

介面上提供「從煎台開始」選項（跳過 `PICKUP`、`PLACE`），對應階段 A、B，
階段 C 之後也保留，方便除錯。

### 煎的時間與翻面次數（現場調參）

不寫死在手臂程式裡，全部放在 Python 參數（草案 `config_phase.FryParams`）：

| 參數 | 說明 | 初始值 |
|---|---|---|
| `FIRST_SIDE_SEC` | 第一面煎幾秒 | 【試】 |
| `FLIP_COUNT` | 翻幾次面（原廠程式是 2） | 2 |
| `SIDE_SEC` | 每次翻面後煎幾秒 | 【試】 |
| `REST_SEC` | 起鍋前最後等待 | 0 |

- 觸控介面的維修頁可以直接改這些數值並存檔（同 V1 切片厚度的做法，存在 `src/settings/`）。
- 每次試煎記錄：肉排重量、厚度、煎台溫度、秒數、熟度結果，累積成對照表後再定預設值。
- 【待確認】要不要用溫度計（探針或紅外線）判斷熟度，取代純計時。

## 4. 組裝漢堡

【待確認】完整配料與順序，暫定（由下往上）：

1. 下層麵包
2. 生菜
3. 肉排
4. 起司（可在煎台上最後一面時放上去融化）
5. 番茄片
6. 上層麵包

要決定的事：

- **配料前處理**：番茄、生菜是事先人工切好，還是用 V1 的切菜功能現切？（V1 的切割流程可沿用）
- **組裝位置**：直接在盤子上疊，還是在組裝區疊好再整個移到盤子？
- **夾取方式**：麵包、起司片、番茄片很軟或很薄，平鏟能不能鏟起來，還是需要另一種夾爪？
- **起司**：要不要在煎台上融化？

## 5. 平鏟機構設計

這次翻面工具重新設計，需求如下：

| 需求 | 說明 |
|---|---|
| 耐熱 | 長時間接觸煎台；鏟面、固定座、螺絲都要耐熱，熱不要傳到手臂法蘭 |
| 薄的前緣 | 前緣要薄、有斜角，才能鏟進肉排底下，不把肉排推走 |
| 鏟面大小 | 能整片托住肉排（肉排直徑 +20 mm 以上）【待確認肉排尺寸】 |
| 剛性 | 鏟起時不能晃，以免肉排滑落 |
| 角度 | 鏟入時要能貼平煎台，安裝角度要配合手臂可達的姿態 |
| 安裝 | 固定在法蘭上，安裝位置可量測，教點用的工具座標（`TOOL`）要能寫進程式 |
| 清潔 | 可拆下清洗（食品接觸面） |
| 碰撞保護 | 建議有一點彈性或過載保護，避免下壓過深撞壞煎台或手臂 |

要決定的事：

- 兩臂都換成平鏟，還是一支平鏟、一支保留其他工具（例如夾爪做組裝）？
- 需不需要換刀（自動換工具），還是一支工具做完翻面、鏟起、組裝？

機構定案後，在 `config_objects.ToolType` 加上新工具，並更新手臂程式的 `TOOL` 偏移量。

## 6. 參考：原廠 `fry_burger` 動作

`V1/robot/原程式/rs_f.as`、`rs_r.as` 裡已經有一套 `fry_burger`（`$dish == "BURGER"` 時呼叫），
V2 手臂程式以它為起點，拆成可以分段下指令的子程式：

| 原廠點位 | 動作（依程式註解） | V2 對應 |
|---|---|---|
| `fr1` | 準備位置 | `FLIP` 開始 |
| `fr2`、`fr15`/`fr3`、`fr16`、`fr14`、`fr6` | 鏟入 → **翻面** → 退開，重複 2 次 | `FLIP` |
| `fr7` → `fr8` → `fr9` | 下降 → **鏟起** → 抬升 | `SCOOP` |
| `fr10` → `fr11` → `fr12` → `fr13` → `fr14` | 移動 → 下降 → 抬升 → 橫移 → 下降 | `SCOOP` 搬運 |
| `fr16`（右臂，50 mm/s） | **撥下**到盤子 | `ASSEMBLE` 放肉排 |
| `fr15` → `fr1` | 退回 | `HOME` 前 |

- 兩臂用 `SIGNAL 1` / `SWAIT 1001` / `PULSE 1` 互相等待，每一步都同步。V2 保留這個做法。
- 速度：一般 200 mm/s，撥下時降到 50 mm/s。
- 換成新平鏟後，所有 `fr*` 點位都要在 V2 的煎台位置**重新教點**。
- 翻面次數改由 Python 端的 `FLIP_COUNT` 控制，手臂程式一次只翻一面。

## 7. 相對 V1 要改的地方

### 流程層（`config_phase.py`、`phase_controller_skeleton.py`）

- 新增階段 `FRY`（等待計時，不動手臂）、`SCOOP`（鏟起搬運）、`ASSEMBLE`（組裝）。
- 沿用 `FLIP`，意思從「翻炒」改成「翻一次面」。
- 拿掉 `MEASURE`；`CHOP` 先保留，視配料是否現切再決定。
- `MENU` 只留 `BURGER`，另加「從煎台開始」的變化（階段 A、B 用）。

### 指令層（`config_commands.py`）

| 指令 | 格式（草案） | 說明 |
|---|---|---|
| `FLIP` | `FLIP,PATTY,<SPEED_PERCENT>` | 翻一次面 |
| `SCOOP` | `SCOOP,PATTY,<目的地>` | 鏟起並搬到目的地上方 |
| `PLACE` | 沿用 `PLACE,<SOURCE>,<LOCATION>,<METHOD>`，`METHOD` 加 `PUSH`（撥下） | |
| `ASSEMBLE` | 【待確認】依組裝方式決定 | |

`FRY` 不送指令給手臂，只在 Python 端計時並在介面上顯示倒數。

### 物件定義（`config_objects.py`）

- `FoodType`：`PATTY`（肉排），以及組裝用的 `BUN_BOTTOM`、`BUN_TOP`、`CHEESE`、`LETTUCE`、`TOMATO`（依第 4 節定案）。
- `LocationPoint`：`PICKUP_PATTY`、各配料取料點、`GRIDDLE`（煎台）、`ASSEMBLY_ZONE`（組裝區）、`BURGER_PLATE`（成品盤）。
- `ToolType`：新平鏟（見第 5 節）。

### 手臂程式（`robot/`）

- 從 V1 的 `F60_F_左臂_GBK.as`、`F60_R_右臂_GBK.as` 複製一份到 V2，保留 TCP 指令分派與握手，
  移除切沙拉專用的部分，加上由原廠 `fry_burger` 拆出的 `do_flip`、`do_scoop`、`do_push_off`。
- 新教點：煎台的 `fr*` 系列、`PICKUP_PATTY`、配料取料點、組裝區、成品盤。

### 視覺（重新訓練 YOLO）

用 `V1/automation-2026-yolo-main/` 的訓練流程（拍照 → 標註 → `splitdata.py` → `train.py`）訓練 V2 模型，放到 `V2/src/models/`。

| 類別（草案） | 用途 |
|---|---|
| `PATTY_RAW` | 取料區生肉排定位 |
| `PATTY_COOKED` | 煎台上肉排位置；翻面後確認還在煎台上 |
| `BUN_BOTTOM`、`BUN_TOP` | 麵包定位 |
| `CHEESE`、`LETTUCE`、`TOMATO` | 配料定位（依第 4 節定案） |

- 生熟肉排顏色差很多，要分開收資料，而且要在**加熱中的煎台上**拍（油煙、反光、熱氣）。
- 相機要避開油煙直衝的位置，必要時加擋板或換角度；曝光要現場重新調。
- 肉排是圓的，不需要 V1 的頭尾判斷；YOLO 框中心就夠用。
- 第 3 節的階段 A、B 可以先不靠視覺（固定煎台位置），讓模型訓練與機構、手臂教點同時進行。

### 觸控介面（`web_ui.py`、`templates/index.html`）

- 菜單只有「漢堡」，加上「從煎台開始」選項。
- `FRY` 階段顯示每一面的倒數。
- 維修頁可以調 `FryParams`。

## 8. 安全（真的加熱）

- **燙傷**：煎台運作中禁止觀眾接近，展台要有圍欄或距離標示；工作人員放肉排時戴隔熱手套。
- **手臂與工具**：`FRY` 等待期間兩臂離開煎台上方，避免工具和法蘭被長時間烘烤。
- **鏟子撞擊**：鏟入煎台時用低速、限制下壓量，教點時先在冷的煎台上確認。
- **火源與油**：煎台要有獨立的電源開關，展場人員能隨時關掉；附近不放易燃物，準備滅火器（油類火災適用）。
- **失敗處理**：沿用 V1 規則，流程中途失敗不自動復歸。但肉排會繼續煎：
  失敗時介面要提示「先關煎台或移開肉排」，再人工把手臂移回原點後重啟。
- 介面「停止」鍵仍不是安全裝置，緊急停止請用實體急停。
