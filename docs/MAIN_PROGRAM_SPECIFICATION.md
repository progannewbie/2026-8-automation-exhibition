## 架構設計

### 三層架構

```
應用層 (Application)
  ├─ 菜單界面 (Menu UI)
  ├─ 用戶交互 (User Input)
  └─ 進度顯示 (Progress Display)
         ↓
控制層 (Control)
  ├─ PhaseController (流程控制)
  ├─ CommsManager (通訊管理)

         ↓
底層 (Infrastructure)

  ├─ F60_R Robot (右臂)
  └─ USB Camera (相機)
```

## 初始化流程

### 啟動序列

```
程序開始
  ↓
1. 配置載入
   ├─ 加載 config_*.py 常數
   ├─ 設置日誌級別
   └─ 驗證環境 (Python 版本、依賴套件)
  ↓
2. 硬件初始化
   ├─ 初始化 CommsManager
   ├─ 連接 F60_F + F60_R
   ├─ 檢查連接狀態 (STATUS 查詢)
   └─ 報告連接結果
  ↓
3. 視覺系統初始化
   ├─ 初始化 VisionSystem
   ├─ 加載 YOLO 模型
   ├─ 初始化 ArUco 檢測器
   └─ 載入 Hand-eye 標定數據
  ↓
4. 流程控制器初始化
   ├─ 創建 PhaseController 實例
   ├─ 傳入 vision + comms
   └─ 預載四菜色食譜
  ↓
5. 確認就緒
   ├─ 兩臂回到 HOME 位置
   ├─ 相機自檢 (拍攝測試圖)
   ├─ 顯示就緒提示
   └─ 進入菜單
```


### 狀態轉換

```
IDLE (菜單待機)
  ├─ 用戶選擇 1-3 → EXECUTING (單品)
  ├─ 用戶選擇 4 → CONFIRMING (連續模式確認)
  ├─ 用戶選擇 ? → HELP (幫助)
  └─ 用戶選擇 q → EXITING (退出)

CONFIRMING (連續模式確認)
  ├─ 用戶確認 → EXECUTING (連續菜色)
  └─ 用戶取消 → IDLE

EXECUTING (執行中)
  ├─ 成功完成 → REPORTING (顯示報告)
  ├─ 失敗 → REPORTING (顯示失敗報告)
  └─ 用戶中斷 (Ctrl+C) → CLEANUP (清理)

REPORTING (報告)
  └─ 按 Enter → IDLE

CLEANUP (清理)
  ├─ 機器人回 HOME
  ├─ 斷開連接
  └─ 結束程序

EXITING (退出)
  ├─ 保存日誌
  ├─ 報告統計信息
  └─ 程序終止
```

## 異常處理

### 可恢復的異常

| 異常 | 原因 | 處理方式 | 結果 |
|------|------|---------|------|
| 取料失敗 | 食材位置不對 | 自動重試 3 次 | 失敗 → 終止菜色 |
| 切割失敗 | 鏟子卡住 | 自動重試 3 次 | 失敗 → 終止菜色 |
| 放置失敗 | 目標位置不對 | 自動重試 3 次 | 失敗 → 終止菜色 |
| 連接超時 | 網絡延遲 | 重建連接 (3 次) | 失敗 → 終止菜色 |

**用戶可手動干預**:
- 調整食材位置，選擇相同菜色重試
- 檢查機器人和相機，重新啟動

### 不可恢復的異常

| 異常 | 原因 | 處理方式 | 結果 |
|------|------|---------|------|
| 機器人斷開 | 網線拔除 | 立即停止 | 終止菜色 + 報警 |
| 相機故障 | 設備損壞 | 停止視覺操作 | 無法執行需要視覺的菜色 |
| 復歸失敗 | 機器人異常 | 不重試 (危險) | 終止 + 緊急停止 |
| 翻炒失敗 | 機制卡住 | 不重試 | 終止菜色 |

**需要手動恢復**:
- 檢查機器人硬件
- 重啟程序
- 聯繫技術人員

### 異常日誌

```
每個異常都記錄:
  ├─ 時間戳
  ├─ 異常類型
  ├─ 堆棧跟蹤

  ├─ 重試次數
  └─ 恢復動作

日誌保存位置:
  logs/smartcook_YYYY-MM-DD_HHMMSS.log
```

```python
class SmartCookApp:
    """主程序狀態"""
    
    state: ProgramState
      ├─ INIT (初始化)
      ├─ READY (就緒)
      ├─ EXECUTING (執行中)
      ├─ PAUSED (暫停) [選擇 1-3 時可用]
```
